# Учебный проект: Клиент-серверное приложение тестирования по ТиМП

Данный проект представляет собой законченное клиент-серверное приложение, разработанное в рамках учебного курса **«Технологии и методы программирования» (ТиМП)**. Приложение предназначено для проведения автоматизированного тестирования пользователей по различным математическим и алгоритмическим дисциплинам с возможностью ведения базы данных, учета статистики и валидации результатов на стороне сервера.

Проект демонстрирует практическое применение принципов объектно-ориентированного проектирования (ООП), архитектурных паттернов, многопоточного/асинхронного сетевого взаимодействия через сокеты и интеграцию с реляционными базами данных.

## Основной функционал

### Клиентская часть:
* **Авторизация и Регистрация:** Безопасное разделение сессий пользователей. Форма валидации полей ввода на стороне клиента.
* **Управление окнами (Мультиформенность):** Динамическое переключение интерфейсов (Авторизация $\rightarrow$ Главное меню $\rightarrow$ Прохождение теста $\rightarrow$ Статистика) без утечек памяти.
* **Интерфейс тестирования:** Отображение сгенерированных сервером задач и отправка ответов в реальном времени.
* **Просмотр личной статистики:** Получение актуальной информации о пройденных тестах напрямую из СУБД.

### Серверная часть:
* **Многопользовательский TCP-сервер:** Одновременная обработка пула независимых клиентских подключений за счет асинхронной модели обработки сигналов и слотов Qt.
* **Протокольный парсинг команд:** Выделенный текстовый протокол обмена данными (команды вида `auth <login> <pass>`, `stata <login>`).
* **Интегрированное вычислительное ядро:** Автоматическое генерирование задач и вычисление эталонных ответов на сервере:
    * *Задача 1:* Поиск кратчайшего пути на графах (Алгоритм BFS).
    * *Задача 2:* Численное интегрирование по методу Симпсона с оценкой погрешности.
    * *Задача 3:* Решение обыкновенных дифференциальных уравнений (ОДУ) методом Эйлера.
    * *Задача 4:* Интегрирование разрывных функций методом прямоугольников по непрерывным сегментам.
* **Персистентность данных:** Хранение учетных записей, хэшированных данных и результатов тестирования в локальной СУБД SQLite.

## Архитектура и Паттерны проектирования

Приложение разделено на два независимых исполняемых модуля, взаимодействующих по сетевому протоколу TCP/IP через порт по умолчанию `33333`.

### Паттерны, примененные в проекте:
1.  **Singleton**:
	- На клиенте: `MyTcpClient` (единая точка отправки сетевых пакетов) и `ClientController` (управление состоянием данных).
    * На сервере: `Database` (гарантирует единственный пул подключений к SQLite из любого программного модуля).
    * *Особенность реализации:* Использование вспомогательных классов-деструкторов (`Destroyer`) для гарантированного автоматического освобождения памяти при закрытии приложений.
2.  **Dispatcher**
    * Класс `CommandParsing` на сервере выступает единым интерфейсом для обработки сырых сетевых строк, изолируя логику TCP-сервера от математических вычислений и SQL-запросов.
3.  **Loose Coupling:**
    * Графический интерфейс (UI) ничего не знает о сетевой реализации. Окна взаимодействуют только со слоем бизнес-логики (`ButtonHandler` и `ClientController`), что соответствует принципам SOLID (в частности, SRP - Принципу единственной ответственности).

## Структура классов проекта

### Клиент (Client)
* `main.cpp` - Точка входа, инициализация главного цикла событий Qt.
* `ManagerForm` - Центральный координатор интерфейса, управляющий жизненным циклом и отображением окон.
* `authregform`, `MainForm`, `TEST` - Классы виджетов графического интерфейса (форм).
* `ButtonHandler` - Промежуточный слой обработки сигналов от кнопок UI.
* `ClientController` - Синглтон-контроллер, формирующий протокольные строки для отправки.
* `MyTcpClient` - Синглтон-обертка над низкоуровневым сокетом `QTcpSocket`.

### Сервер (Server)
* `main.cpp` - Инициализация консольного серверного приложения.
* `MyTcpServer` - Сетевой контроллер на базе `QTcpServer`. Управляет пулом сокетов подключенных клиентов (`mSockets`) и осуществляет накопление данных в индивидуальные буферы (`mBuffers`).
* `CommandParsing` - Парсер входящего строкового протокола.
* `Database` - Синглтон-ядро СУБД SQLite, содержащее в себе также реализацию всех математических алгоритмов (Эйлер, Симпсон, BFS) и структуру `EulerTask`.

## Сборка и запуск

Для компиляции и запуска проекта необходим установленный фреймворк Qt и среда разработки Qt Creator (либо утилита `qmake` из консоли).

### Шаг 1: Запуск сервера
1. Откройте файл `server.pro` в Qt Creator.
2. Выполните сборку (Ctrl+B) и запустите сервер (Ctrl+R).
3. В консоли сборки должно появиться сообщение: `server is started on port 33333`.

### Шаг 2: Запуск клиента
1. Откройте файл `client.pro` в отдельном окне Qt Creator.
2. Выполните сборку и запустите приложение.
3. Клиент автоматически попытается подключиться к хосту `127.0.0.1:33333`. При успешном подключении откроется форма авторизации.
